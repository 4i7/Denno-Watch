# 目的

重大事故の最中に最も危険なのは、情報不足そのものより、**情報不足を無視して一つの数字や印象だけで判断すること**である。

- 端末10台感染でも認証基盤が奪われていれば重大。
- 100万件のデータが存在していても取得された件数は未確定かもしれない。
- サービス停止がなくても本人確認書類や認証情報の流出は重大。
- 全面停止すれば侵害拡大を抑えられても、医療・物流・交通・金融では停止自体が重大被害になる。

本資料は、速度・範囲・確度・事業影響を別々に観測し、経営判断へ変換するための共通枠組みを提供する。

# 指標を4群に分ける

## 1. 速度

| 指標 | 定義 | 用途 |
| --- | --- | --- |
| 検知時間 | 最初の確認可能な侵入から検知まで | 攻撃者の自由行動時間を見る |
| 判断時間 | 検知から封じ込め方針決定まで | 組織の意思決定速度を見る |
| 封じ込め時間 | 検知から主要な拡大経路停止まで | 実対応速度を見る |
| 技術復旧時間 | 検知・停止から主要システム再稼働まで | IT復旧力を見る |
| 業務復旧時間 | 業務影響開始から許容水準復帰まで | レジリエンスを見る |
| 影響範囲確定時間 | 検知から対象データ・人数・下流の十分な精査まで | フォレンジック・データ管理能力を見る |
| 通知開始時間 | 発覚から必要な当局・本人・顧客への初報まで | 法務・広報・顧客対応能力を見る |

公開情報で起点が不明な場合は無理に計算しない。

## 2. 被害範囲

件数は単位を混ぜない。

- 影響端末数。
- 影響サーバー・システム数。
- 影響拠点・店舗数。
- 影響顧客・委託元組織数。
- 最大影響可能性のある人数・アカウント・レコード数。
- 確認済み取得・流出数。
- 通知対象数。
- 停止した重要業務数。
- 下流の社会・供給影響。

「660万アカウント」と「160万件の本人確認書類」のように異なる母集団を一つの数字へ潰さない。

## 3. 証拠確度

同じダッシュボード上でも、事実と仮説を分離する。

| 状態 | 判断 |
| --- | --- |
| 確認済み | 一次資料・フォレンジック等で確認 |
| 可能性あり | 否定できない、または調査対象 |
| 未観測 | 現時点の調査で証拠なし |
| 非公表 | 組織が公表していない |
| 不明 | 公開情報では判断不能 |

経営会議で「流出なし」と言う前に、それが `未観測` なのか、本当に調査で否定できたのかを確認する。

## 4. 事業能力

サイバー指標だけでなく、業務能力を測る。

- 通常処理量に対する現在の処理率。
- 代替業務で処理できる割合。
- 安全・医療・物流・決済等の重要機能の残存能力。
- 顧客問い合わせ・通知処理能力。
- 手作業へ切り替えた際の持続可能時間。
- 現金、在庫、配送、請求等の滞留量。
- 復旧に必要な第三者の稼働状態。

# 最初の60分で答える8問

完全な原因究明を待たず、次を優先する。

1. **今も攻撃者が活動している可能性はあるか。**
2. **どの認証情報・管理面・ネットワーク境界が信用できないか。**
3. **安全、人命、金融、物流等で停止自体が危険な業務はあるか。**
4. **被害が広がる主要経路を今止められるか。**
5. **証拠保全前に失われるログ・メモリ・クラウド状態はあるか。**
6. **顧客・委託元・規制当局へ速報が必要な可能性はあるか。**
7. **クリーンな連絡手段と意思決定権者を確保したか。**
8. **バックアップ・復旧環境も侵害された可能性はあるか。**

CISAはランサムウェア対応で、影響システムの即時隔離、必要に応じたネットワーク停止、証拠保全、重要サービス優先のクリーン環境復旧を示している。初動では原因の完全解明より、拡大防止と復旧可能性の確保が先になる。

# エスカレーション基準

## 最優先 — 経営・法務・広報・事業責任者を即時招集

次のいずれかを満たす場合の目安。

- 認証基盤、管理者権限、バックアップ管理面の侵害可能性。
- ランサムウェア、広範な暗号化・削除。
- 100万件級または高感度データへのアクセス可能性。
- 本人確認書類、認証情報、健康、金融、マイナンバー等。
- 複数顧客・委託元・テナントへの波及可能性。
- 医療、物流、交通、金融、通信等の重要業務停止。
- 攻撃者による公開・恐喝・二次攻撃。
- 原因不明のまま被害が拡大中。

P0は「最終的に重大事故だった」と確定してから宣言する状態ではなく、**重大化する可能性があり、意思決定遅延のコストが高い状態**である。

## 高優先対応

- 単一サービス・限定範囲だが外部侵入を確認。
- データ取得可能性があり精査中。
- 主要業務への影響は限定的。
- 侵入経路または被害範囲を短時間で限定できる見込み。

## 通常インシデント管理

- 影響範囲が限定され、侵害拡大経路を遮断済み。
- 高感度データ・重要業務への到達を合理的に否定できる。
- 通常のIR手順で収束可能。

P2から開始しても新情報でP0へ上げる。初期分類を守ることより、証拠に合わせて更新することが重要である。

# 全面停止か部分隔離か

| 条件 | 全面停止へ傾く | 部分隔離へ傾く |
| --- | --- | --- |
| 攻撃者の活動 | 広範・継続・位置不明 | 経路と対象を高確度で限定 |
| 認証基盤 | 信用不能 | 独立した安全領域がある |
| 横展開 | 複数セグメント・管理面へ到達 | 強い分離境界が維持 |
| 安全・社会影響 | 停止より侵害継続が危険 | 停止自体が人命・供給へ重大影響 |
| 代替手段 | 代替業務あり | 代替不能で停止損失が極端に大きい |
| 証拠確度 | 低く急速に悪化 | 高く監視可能 |

実際には「全部止める／止めない」の二択ではなく、外部共有、VPN、管理面、データエクスポート、特定テナント、特定API等を**個別に強制停止できる設計**が最も強い。

# 復旧開始の条件

急いで戻すほど再侵入・再暗号化のリスクがある。最低限、次を確認する。

- 侵入経路または主要な再侵入経路を封じた。
- 侵害された可能性のある認証情報を失効・交換した。
- 復旧元のバックアップ・イメージが合理的に信頼できる。
- クリーンな復旧ネットワークまたは隔離領域がある。
- 重要サービスの復旧優先順位が定義済み。
- 復旧後の監視を強化できる。
- 影響システムから必要証拠を保全した。

# 復旧完了の条件

「ユーザーがログインできた」だけでは完了ではない。

1. 重要サービスが必要な処理量で安定稼働。
2. 侵害経路と主要な永続化を是正。
3. 認証情報・鍵の交換範囲が完了。
4. バックアップ・DRを含め信頼境界を再確立。
5. 影響範囲と通知対象の精査が十分に進展。
6. 必要な通知・規制・顧客対応を実施。
7. 強化した監視で異常な再活動が観測されていない。
8. 恒久対策の所有者・期限・検証方法を確定。

技術復旧だけ完了した場合は `technical_restored`、業務まで戻れば `business_restored` とし、公開記録の収束とは分ける。

# 防御能力を測る先行指標

事故件数は結果指標であり、偶然ゼロにもなる。平時は次を測る。

## アイデンティティ

- 外部アクセスのMFA適用率。
- フィッシング耐性MFA適用率。
- 90日超の未使用特権アカウント数。
- 長寿命トークン・静的キー数。
- 委託先アカウントの所有者不明率。

## 資産・脆弱性

- インターネット公開資産の所有者確定率。
- Critical/KEV脆弱性の24時間・72時間以内対応率。
- 未管理・未監視サーバー数。
- EDR/NDR/ログ未適用重要資産数。

## データ

- 所有者不明データセット数。
- 保持期限超過データ量。
- 本番データを持つ分析・開発環境数。
- 顧客・テナント間で共有される管理権限数。

## 復旧

- 重要業務ごとの直近復元演習日。
- 実測RTO/RPOと目標との差。
- 本番認証基盤から独立したバックアップ割合。
- 代替業務を実運用へ切り替えるまでの時間。

## 第三者

- 重要第三者のMFA・ログ・復旧証跡確認率。
- 重要第三者で再委託先不明の割合。
- 代替不能な単一提供事業者数。
- 委託先端末から直接管理アクセスできる重要システム数。

# 経営会議の10問

重大事故時、製品名やマルウェア名より先に次を確認する。

1. 最悪の場合、何が止まり、誰のデータが、何件規模で影響し得るか。
2. 今この瞬間に被害は拡大しているか。
3. どの境界・認証情報を信用できないか。
4. 何を止めれば拡大を最も減らせるか。
5. その停止で人命・供給・顧客へどの二次被害が出るか。
6. クリーンな復旧手段はあるか。最後に試したのはいつか。
7. 顧客・委託元・当局へ何をいつ伝える必要があるか。
8. 24時間後、7日後、30日後に必要な判断は何か。
9. 今後数年残り得る本人保護・契約・訴訟・信用リスクは何か。
10. 同じ事故をもう一度起こさないことを、何で検証するか。

時間が公表されていない場合、報道時刻等から推定して埋めない。

# Denno Watchでの使い方

本資料は企業を採点するためではなく、事例間で**どの情報が欠けているか**を見えるようにするために使う。

- 侵入経路は分かるが検知契機がない。
- 技術復旧日はあるが業務復旧が不明。
- 最大対象件数はあるが確認済み取得数がない。
- 再発防止策は公表されたが検証状態がない。
- 通知完了は分かるが長期本人保護が不明。

このような欠落自体が、追加調査・将来更新の優先順位になる。
