# 目的

Denno Watchの2026年事例集を過去へ延長する際、「AIが攻撃を変えた」という一文だけで2023年以降を括ると、既に存在していたランサムウェア犯罪基盤、認証情報窃取、内部不正、ゼロデイ、委託先集中、VPN・ネットワーク境界の弱点をAIの効果と誤認する。

本資料では、**ローカルLLMが個人・小規模主体にも現実的な補助道具となった時期を観測期間の開始点として使うが、個別インシデントをLLM起因とはみなさない**。目的は、攻撃者が利用できる自動化・分析・コード生成・文書生成能力が拡大していく時代と、防御側の即応性・統制成熟度がどう交差したかを比較できるようにすることである。

# 観測開始点を2023年とする理由

2023年7月、MetaはLlama 2を研究・商用向けに公開し、モデル重みとコードを提供した。7Bから70Bまでのモデルが利用可能となり、Windowsを含む複数環境で利用しやすい形へ広がった。[^meta-llama2]

同年9月、Mistral AIはApache 2.0でMistral 7Bを公開し、ローカル利用を明示した。後の公式モデル文書では、量子化条件により概算GPUメモリ4GB級まで示されている。これは「クラウドAPIを契約しなければ高度な言語モデルを使えない」という前提が崩れ始めたことを示す。[^mistral7b][^mistral7b-docs]

したがってDenno Watchでは、**2023年をローカルLLM時代の比較観測開始年**とする。ただし、次を意味しない。

- 2023年以降の攻撃がLLMによって実行された。
- LLMがランサムウェア、ゼロデイ、内部不正の主要原因になった。
- 2023年以前には自動化・犯罪サービス化が存在しなかった。
- 攻撃者が特定のモデルを利用したと、公開証拠なしに推定できる。

# AI以前から既に存在した攻撃の産業化

警察庁によれば2023年中の国内ランサムウェア被害報告は197件で、確認できた身代金要求型175件のうち130件、74%が二重恐喝だった。大企業71件、中小企業102件で、企業規模を問わず被害が発生していた。[^npa-ransom-2023]

IPAの2024年版は、2023年に社会的影響が大きかった脅威として、組織向け1位をランサムウェア、2位をサプライチェーン、3位を内部不正、5位をゼロデイ攻撃、10位を犯罪のビジネス化としている。[^ipa-2024]

つまり2023年の時点で、攻撃者は既に次を利用できた。

- RaaS等の犯罪サービス。
- 漏えい認証情報や初期アクセス市場。
- 公開直後の脆弱性悪用。
- フィッシング、標的型攻撃、内部不正。
- 暗号化と窃取を組み合わせた二重恐喝。

ローカルLLMはこの既存基盤の上に、調査、翻訳、文書作成、コード理解、データ選別等を補助し得る新しい汎用層として加わったと捉える。

# 年別の攻撃・防御環境

## 2023年 — 境界防御・VPN・RaaS・内部不正が同時に顕在化

代表事例:

- 名古屋港統一ターミナルシステム — ランサムウェアでコンテナ搬出入停止。
- エーザイ — グループサーバーへのランサムウェア。
- セイコーグループ — ランサムウェアと約6万件の個人データ流出。
- LINEヤフー／NAVER Cloud — 委託先・認証基盤・ネットワーク接続を経由した侵害。
- NTT西日本グループ — 長期間の内部不正による顧客情報持ち出し。
- JAXA — VPN脆弱性から横展開し、Microsoft 365へ正規利用者を装って到達。
- カシオ ClassPad.net開発環境 — セキュリティ設定解除状態による不正アクセス。

この年の重要点は、攻撃者側にAIがなければ成立しない事故が中心だったのではなく、**既知の境界・委託・権限・監視・設定管理の問題だけで重大事故が成立していた**ことである。

一方で防御側は、MFA、EDR、CSIRT、SOC、ゼロトラスト、バックアップ、BCP等を既に掲げていた企業が多い。ただし「導入済み」という記述と「全社・全拠点・全端末・委託先まで一貫適用」は別だった。

## 2024年 — 大規模事業停止と共有基盤・管理境界の弱点

代表事例:

- KADOKAWA／ドワンゴ — データセンター侵害からニコニコ、出版、経理等へ大規模波及。
- イセトー — ランサムウェアで多数の委託元・自治体等へ個人情報影響。
- DMM Bitcoin／Ginco — 開発者を狙ったソーシャルエンジニアリングから暗号資産約4,502.9 BTCを窃取。
- カシオ — ランサムウェア、グローバルネットワークとフィッシング対策の不備を自社が原因として公表。
- 富士通 — 業務PC起点のマルウェア侵害。
- 日本航空 — 年末の大量通信によるシステム障害。

IPAの2025年版では、2024年の重大脅威としてランサム攻撃、サプライチェーンや委託先、システム脆弱性、内部不正、DDoS等が上位に残った。[^ipa-2025]

ここでは「高度な新攻撃」だけでなく、セキュリティを専門事業として持つ企業や、大規模DXを進める企業でも、古い境界、第三者製品、グローバル統制差、開発者端末、管理権限が弱点となり得ることが明瞭になった。

## 2025年 — セキュリティサービス・共有インフラ・ゼロトラスト移行途中が攻撃面に

代表事例:

- NTTコミュニケーションズ — 法人向けオーダ情報流通システムへの侵害。
- IIJ Secure MX — メールセキュリティサービスで当時未発見の第三者製ソフトウェア脆弱性が悪用され、サービス利用者の認証・メール情報へ影響。
- アサヒグループ — 拠点ネットワーク機器から侵入し、約10日間の偵察後にランサムウェア。ゼロトラスト移行前端末が被害。
- アスクル — EC・物流を長期停止させるランサムウェア、クラウドへの二次アクセス、情報漏えい、巨額の事業・財務影響。

この段階では「ゼロトラスト」「SOC」「EDR」「MFA」を掲げること自体は珍しくない。差が出るのは、**例外資産、旧端末、海外・子会社、外部SaaS、第三者製品、復旧系、サービス間の認証情報まで統制が連続しているか**である。

## 2026年 — AIリスクが独立した経営・防御課題へ

IPAの2026年版では、組織向け脅威に「AIの利用をめぐるサイバーリスク」が初めて3位として選出された。一方、1位はランサム、2位はサプライチェーン・委託先、4位は脆弱性悪用であり、AIだけが独立して既存リスクを置き換えたわけではない。[^ipa-2026]

Denno Watchの2026年42件でも、認証情報、API、SaaS、共有基盤、ゼロデイ、ランサムウェア、データ保持、制御面の悪用等が主要な失敗構造として観測される。

# 即応性を比較する共通軸

過去年の事例でも、単に「対応した／しなかった」とせず次を記録する。

| 軸 | 観測内容 |
| --- | --- |
| 検知源 | 自社監視、利用者、外部組織、攻撃者公開、取引先等 |
| 検知遅延 | 最古の侵害活動から検知まで。ただし推定不能なら空欄 |
| 初動 | 通信遮断、ネットワーク分離、端末隔離、資格情報無効化等 |
| 意思決定速度 | 全面停止・部分停止をいつ決めたか |
| 証拠保全 | ログ、フォレンジック、外部専門家を利用したか |
| 外部連携 | 警察、JPCERT/CC、IPA、PPC、所管省庁、ベンダー |
| 代替運用 | 手作業、代替システム、縮退運転、物流継続 |
| 復元 | バックアップ、クリーン再構築、安全性確認 |
| 公表 | 初報、続報、訂正、本人通知、顧客通知、IR開示 |
| 長期追跡 | 行政指導、財務、訴訟、再発防止、組織変更、再発 |

# 「事故前のセキュリティ開示」の読み方

統合報告書、サステナビリティ資料、情報セキュリティ方針に「CISO」「CSIRT」「MFA」「EDR」「ゼロトラスト」「ISMS」等が記載されていても、次を証明しない。

- 侵害資産へ同じ統制が適用されていた。
- 海外拠点、委託先、旧端末、開発環境まで展開済みだった。
- 設定が正しく保守されていた。
- 監視が攻撃経路のログを取得していた。
- 復旧に必要な依存系が分離されていた。

したがって各事例では、**公表済み統制 → 実際に破られた境界 → 事故後に追加された統制**を三列で比較する。

# ローカルLLM時代に追加で見るべき防御観点

公開根拠がない限り攻撃へのAI利用を断定しない一方、防御設計としては次を前提とする。

1. 偵察・文書生成・翻訳・コード理解の単価は低下し得る。
2. 自社運用モデルならAPI拒否、利用停止、提供者監視を防御境界にできない。
3. 小規模主体でも複数ツールを連携した長時間の反復作業が容易になる。
4. 攻撃者の能力向上だけでなく、防御側もログ解析、コード監査、調査補助へAIを使える。
5. したがって「人間が手作業で攻撃する速度」をインシデント初動の前提にしない。
