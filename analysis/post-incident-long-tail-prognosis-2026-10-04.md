# 要旨

サイバーインシデントの「復旧」は、長期予後の開始点である場合が多い。サービスが再開しても、盗まれたデータは回収できず、本人通知、二次悪用監視、規制対応、契約責任、訴訟、保険、信用回復、再構築費用は数か月から数年続く。

Denno Watchでは、事故の終端を「Webサイトが戻った」「基幹システムが動いた」だけで決めない。本資料は、個別事例の `現在の状況と予後` を一貫した観点で更新するための横断知識基盤である。

# 長期予後を8領域に分ける

## 1. 本人保護と二次悪用

漏えいした情報の危険性は、公開件数だけで決まらない。

高い長期性を持つ例:

- 氏名、生年月日、住所、電話番号等の基礎属性。
- メールアドレスと利用サービス情報。
- パスワード、認証質問、トークン等の認証情報。
- 運転免許証、旅券、本人確認画像等の本人確認書類。
- 健康、保険、診療、雇用、給与、金融情報。
- 購買履歴、配送先、位置・移動関連情報。

パスワードは変更できても、生年月日や過去の本人確認書類は簡単には変更できない。したがって、漏えい後のリスク期間はデータ種別ごとに異なる。

### 追跡すべき二次被害

- 標的型フィッシング、スミッシング、なりすまし。
- アカウント乗っ取り、パスワード再利用攻撃。
- 本人確認回避、口座・契約・ローン等への悪用。
- 攻撃者サイトや犯罪フォーラムでの再掲・再販売。
- 顧客や従業員を騙る取引先詐欺。

**二次悪用が観測されていないことは、将来の悪用可能性がないことを意味しない。** Denno Watchでは `not_observed` と「発生していない」を分ける。

## 2. 規制・行政対応

日本では、個人データの漏えい等が報告対象となる場合、個人情報保護委員会は速報を発覚から概ね3〜5日以内、確報を原則30日以内、不正目的のおそれがある場合は60日以内と案内している。本人通知も状況に応じて速やかに行う。

このため規制対応には少なくとも次の段階がある。

1. 報告対象かの初期判定。
2. 速報。
3. 影響範囲の精査。
4. 本人通知・取引先通知。
5. 確報・追加報告。
6. 規制当局からの照会・調査。
7. 是正策・再発防止策の実施。
8. 追加の監督・検査・報告がある場合の継続対応。

業種ごとの規制は別に存在し得る。金融庁は、サードパーティリスク、ITレジリエンス、フィッシング耐性のあるMFA、AIによる脅威変化等を継続的に監督・調査テーマとして扱っている。

## 3. 契約・下流責任

受託事業者、SaaS、BPO、クラウド、共同基盤の侵害では、主被害組織の復旧後も顧客企業側の対応が続く。

- 顧客ごとの影響判定。
- 顧客からの調査票・証拠要求。
- 契約上の通知義務。
- 顧客が本人通知するための情報提供。
- 補償・違約・求償・費用分担。
- 再契約、監査、追加セキュリティ条件。
- 再委託先を含む連鎖的な調査。

一件の技術事故が、数十・数百の顧客企業で別々の法務・広報・規制対応を発生させることがある。

## 4. 訴訟と法的残存リスク

海外比較ケースは、技術復旧と法的収束の時間差を明確に示す。

- **MOVEit Transfer**: 2023年のゼロデイ悪用から3年以上経過した2026年8月末でも、多地区訴訟は継続し、集団認定に関する手続が進んでいる。Progressは今後12か月以内に終了しない見込みとしている。
- **Snowflake顧客アカウント侵害**: 2024年の事案について2026年7月末でも米国の多地区訴訟、カナダの集団訴訟、規制・議会関係の照会が残る。
- **Caesars Entertainment**: 2023年の本人情報流出について、後年の年次報告でも集団訴訟等が記載されている。

日本と米国では訴訟制度・損害賠償・規制が異なるため、金額や法的義務を直接移植してはいけない。しかし、**技術事故の法的負債が年単位で残る構造**は比較知見として有用である。

## 5. サイバー保険と費用回収

事故後の費用は、保険で全額回収できるとは限らない。

追跡すべきもの:

- フォレンジック、法律、広報、通知、信用監視等の直接費用。
- 事業中断、売上・粗利影響。
- 顧客・取引先への補償。
- 復旧・再構築・追加クラウド費用。
- 保険金請求、免責、上限、対象外判定。
- 保険会社による求償。
- 更新時の保険料・条件変更。

Snowflakeの2026年開示は、関連損失を保険で完全に回収できない可能性や、侵害顧客への補償請求が実務上困難な可能性までリスクとして記載している。MOVEitでも保険会社からの求償が訴訟へ組み込まれている。

## 6. 信用・顧客行動・事業戦略

信用影響は「SNSで炎上したか」だけでは測れない。

- 解約率、更新率、商談失注。
- セキュリティ質問票・監査要求の増加。
- 営業サイクルの長期化。
- 新規サービス・M&A・クラウド移行計画への影響。
- ブランド名と事故が長期に検索結果で結び付くこと。
- 提供事業者側の事故原因でなくても、顧客から責任主体として認識されること。

Snowflakeは、顧客側アカウント侵害が自社プラットフォームの脆弱性・設定不備・企業環境侵害に起因する証拠は確認していないとしつつ、誤認を含む評判悪化や顧客喪失リスクを開示している。

## 7. 技術負債と是正の長期化

事故後には、緊急復旧とは別に長期是正が必要になる。

- レガシー環境の廃止・移行。
- MFA・端末信頼・条件付きアクセスの全社適用。
- ネットワーク・管理面・バックアップ面の分離。
- ログ保持、EDR/NDR/SIEMの拡張。
- データ保持削減、テナント分離、暗号鍵分離。
- 委託先アクセスの再設計。
- DR・BCPの再構築と演習。

「対策を導入した」と「全対象へ適用され例外が管理され、実際に試験した」は別状態として記録する。

## 8. 組織・人員への残存負荷

長期事故では、技術者だけでなく法務、広報、顧客対応、営業、経営、監査、人事まで負荷が広がる。

- 24時間対応や長期調査による疲弊。
- 通常開発・改善計画の遅延。
- 外部専門家・臨時要員への依存。
- 経営会議・取締役会の継続対応。
- 担当者交代で失われる事故知識。

定量化しにくいが、事故後のセキュリティ能力を弱める要因になり得るため、重大事例では記録価値がある。

# 時間軸ごとの観測項目

## 発覚〜72時間

- 被害拡大を止められているか。
- 重要業務と安全への影響。
- 規制・契約上の速報義務。
- 外部支援、法務、経営、広報の招集。
- 証拠が失われる前の保全。

## 30日

- 侵入経路と影響範囲の確度。
- 技術・業務復旧の進捗。
- 本人・取引先通知。
- 攻撃者サイトや二次悪用の監視。
- 初期再発防止策。

## 90日

- データ対象・件数の訂正や確定。
- 主要な再構築の完了状況。
- 復旧演習・監視強化の実効性。
- 顧客・委託元への追加報告。
- 規制当局からの追加照会。

## 1年

- 二次悪用の観測。
- 訴訟・補償・保険の進展。
- 顧客・売上・契約への影響。
- 恒久対策の実装・検証。
- 事故前の技術負債が解消されたか。

## 2〜3年

- 長期訴訟・規制対応の残存。
- 本人保護措置の継続必要性。
- 保険・求償・和解等の財務影響。
- 事故を契機とする事業・サービス廃止や再設計。
- 同種事故が再発していないか。

海外比較ケースではこの期間まで公開情報が蓄積しており、国内の新しい2026年事例の将来観測項目を設計する参考になる。

# 「予後良好」をどう判定するか

単に新しいニュースがないことを予後良好としない。公開根拠で次の多くが確認できる場合に、初めて長期リスクが低下したと評価できる。

- 侵入原因または再侵入条件への恒久対策が完了。
- 主要業務が通常水準へ戻った。
- 影響範囲の精査が完了し、大幅な追加対象が出ていない。
- 必要な通知・規制対応が完了または安定状態。
- 二次悪用が一定期間観測されていない。
- 攻撃者の再アクセス・再掲等が観測されていない。
- 顧客・下流への対応が収束。
- 再発防止策が実装され、演習・監査等で検証された。

それでも、変更困難な本人情報が漏えいした場合は「リスク消滅」ではなく、**新たな公開上の悪化が一定期間観測されていない**という表現が適切である。

# 予後悪化を示すシグナル

- 初報より影響件数・データ種別が拡大。
- 攻撃者サイトや外部流通で実データが確認。
- 同じ侵入経路・同じ資格情報で再侵入。
- 追加の顧客・委託元が影響を公表。
- 規制当局の調査・命令・行政処分。
- 集団訴訟、顧客請求、保険求償。
- サービス再停止、復旧延期。
- 再発防止策の未実施や重大例外の継続。

# 国内で特に長期追跡価値が高い事例

- **タイムズカー**: 本人確認書類を含むため、認証情報変更だけでは消えない長期的な本人保護リスクを持つ。
- **Helpfeel / Gyazo**: 大規模ユーザー母集団と画像メタデータの性質から、後続の範囲訂正・二次影響を追う価値が高い。
- **KDDI**: 共有基盤・認証情報・規制対応の組合せにより、下流・長期観測価値が高い。
- **両毛システムズ／日本テレネット**: 受託データを通じた複数組織への波及と通知完了状態を追う必要がある。
- **マルタケ／日本資産総研／REXT**: ランサムウェア後の攻撃者サイト掲載と、技術復旧後の機密性リスクを分離して追跡する。
- **ドットマネー／ドットギフト**: サービス復旧とサービス廃止が同じ事故の異なる終端状態になった比較価値がある。

# 追加すると有用な予後メタデータ

公開根拠がある場合、個別事例に次を追加できる。

- `prognosis_state`: `active_response` / `recovery` / `long_tail_monitoring` / `public_record_closed` 等。
- `identity_protection_state`: 本人保護・信用監視・注意喚起等。
- `secondary_abuse_last_checked_at`: 二次悪用を最後に確認した時点。
- `litigation_state`: 公表された訴訟等がある場合の状態。
- `insurance_state`: 公表された保険請求・回収・求償の状態。
- `corrective_action_state`: 計画、実装中、実装済み、検証済み。
- `residual_risks`: 公開情報上残る具体的なリスク。
- `closure_basis`: 公開記録を閉じる場合の根拠。

日本企業の事例で公表されていない訴訟・保険・財務影響を推測して埋めてはならない。

# 海外比較ケースから得られる予後の尺度

Change Healthcareでは、2024年の事故後、HHSへの報告上の影響人数は2025年7月末に約1億9,270万人まで更新された。UnitedHealth Groupは2024年に22億ドルの直接対応費と8.67億ドルの事業中断影響を開示し、2025年第4四半期には医療提供者向け融資等の回収見込みに関して7.99億ドルの引当増加を計上した。これは、**影響人数・事業影響・財務影響が別々の時間軸で成熟する**例である。

MOVEitは2023年の脆弱性悪用から2026年後半まで多地区訴訟が続き、Snowflake顧客アカウント事案も2026年に訴訟・規制・評判リスクが残る。Caesarsでも2023年事案の集団訴訟が後年の開示に残る。

日本の法制度へこれらの金額・手続を直接当てはめるものではない。比較対象として重要なのは、**サイバー事故の最終コストは復旧日に確定せず、数年後まで更新され得る**という時間構造である。

# 最終原則

Denno Watchで「現在の状況と予後」を書く際は、次を分ける。

- **現在確認できる状態**: 復旧、調査、通知、監視等。
- **観測された後続影響**: 二次悪用、追加流出、訴訟、規制、契約影響等。
- **残存する合理的リスク**: データ感度・集中構造から防御上追う価値があるもの。
- **不明・未公表事項**: 公開根拠だけでは判断できないもの。

将来被害を断定せず、かといって「今のところ被害報告なし」を安全宣言にも使わない。この中間を保つことが、長期予後を知識として再利用可能にする。
