# 結論

CISO、SOC、EDR、MFA、ゼロトラスト、SASE、ISO/IEC 27001、バックアップ、CSIRT等を事故前に公表していた企業でも重大侵害は発生している。ただし、事故発生だけを根拠に「対策は無意味だった」「公表は虚偽だった」と判断することはできない。

複数事例に共通するのは、**統制の名称ではなく、事故対象資産への実際の適用範囲、例外、移行途上資産、境界機器、特権資格情報、パッチ・ログ運用、データ配置・保持、検知後の侵害範囲確定能力**が被害を左右したことである。

# 共通する失敗類型

## 1. 統制の例外

MFA、監視、EDR等を全社方針として持っていても、委託先用、旧システム、緊急用、共有アカウント等の例外が攻撃面になる。ASKULのMFA例外、PR TIMESの共有アカウント・IP許可例外が明確な例である。

評価指標は「MFA導入済み」「EDR導入済み」の二値ではなく、**対象資産に対する適用率、例外数、例外理由、期限、再承認、廃止確認**を含む必要がある。

## 2. 基本統制の運用品質

エムケイシステムでは、事故前の強い安全性表示と、規制当局が認定した弱い管理者パスワード、重大更新未適用、ログ保管・監視不足が併存した。高度な製品導入以前に、認証、パッチ、ログという基本統制の運用品質が被害を左右する。

## 3. 移行途上・レガシー資産

アサヒのゼロトラスト移行前PC、PR TIMESの旧管理画面のように、新しい統制を導入していても旧経路・旧端末が残れば攻撃面は維持される。

「新方式を導入したか」だけでなく、**旧方式が完全に廃止されたか**を確認する必要がある。

## 4. 境界機器と特権資格情報

VPN、リモートアクセス装置、ネットワーク機器は複数事例で侵入面となった。イセトー、サンリオエンターテイメント、審調社、保険見直し本舗等が該当する。

加えて、ニデックインスツルメンツでは管理者ID・パスワード、ASKULでは委託先管理アカウント、PR TIMESでは共有管理アカウントが主要論点となった。境界資産と特権資格情報を同じ攻撃面管理へ含める必要がある。

## 5. データ配置・保持

イセトーでは、作業効率のための便宜保存と削除不徹底が被害範囲へ影響した。PR TIMESでは削除済みデータを復旧可能な状態で保持する設計が事故後に見直された。

侵入防止だけでなく、**侵害時点にどのデータがどこへ何期間存在するか**が最終的な被害上限を決める。

## 6. 初動、根絶、侵害範囲確定の差

PR TIMESは検知当日に遮断した後も残存プロセスが活動した。ASKULは社内ネットワークの物理遮断後も外部クラウドへの不正アクセスが発生した。NTTコミュニケーションズは最初の装置対応後に別装置の侵害を特定した。

一方、ニデックインスツルメンツでは当日中にEDR等でマルウェアを駆除し、翌日にバックアップから最低限業務を再開したが、情報影響の確定・対象者通知は約2か月続いた。

従って `containment` を一つの時刻にせず、少なくとも `initial_block`、`scope_confirmation`、`credential_reset`、`persistence_eradication`、`clean_restoration` を分ける。

# 「PDFや認証があったのに侵害された」の解釈原則

1. 文書・認証の存在は、統制の設計、宣言、審査範囲の証拠である。
2. 事故発生だけでは、文書が虚偽だった、認証が無意味だったとは判断しない。
3. 実際に侵害された資産、拠点、アカウント、データが、その統制の適用範囲だったかを確認する。
4. 適用範囲だった場合も、設計不足、例外、設定不備、運用逸脱、移行途中、検知回避等を分離する。
5. 一部統制が失敗しても、別の統制が検知、横展開抑止、復旧、被害限定に機能している場合はその効果を残す。
6. 事故後の再発防止策や事故後取得した認証を、事故前統制の証拠として扱わない。
7. 認証停止・再開、行政指導、内部統制評価、株主・財務資料は、技術復旧後の予後として追跡する。

# 平時資料から抽出する項目

企業の統合報告書、セキュリティ報告書、認証資料、IR資料からは、少なくとも次を抽出する。

- MFA、EDR、SOC、SASE、ゼロトラスト等の対象範囲と適用率。
- パスワード規則、特権認証、共有資格情報、委託先資格情報の管理。
- 例外アカウント、例外端末、例外ネットワークの件数、理由、期限。
- 境界機器の資産、脆弱性、パッチ、EOL管理。
- セキュリティ更新の適用期限と重大未適用件数。
- 管理者・委託先アカウントの個人識別、共有禁止、棚卸し。
- データの正規保存領域、一時コピー、削除期限、バックアップ保持。
- ログ対象範囲、保持期間、24時間監視の対象。
- 復元試験、攻撃者から独立したバックアップ、クリーン環境再構築能力。
- 事故後の認証停止、監督当局命令、内部統制評価、役員責任、決算影響。

「当社はセキュリティを強化している」という抽象的記述だけでは、事故対象資産の防御能力を示す強い証拠として扱わない。
