# 結論

事故前にCISO、SOC、EDR、MFA、ゼロトラスト、SASE、ISO/IEC 27001、バックアップ、CSIRT等を公表していた企業でも重大侵害は発生している。ただし、これを「対策は無意味だった」と読むのは誤りである。

今回の再調査で繰り返し確認できたのは、**統制の名称ではなく、実際の適用範囲、例外、移行途上資産、境界機器、資格情報、データ配置・保持、侵害後のスコープ確定能力**が被害を左右したという点である。

# 横断して観測された失敗類型

## 1. 統制の例外

MFA、監視、EDR等を全社方針として持っていても、委託先用・旧システム・緊急用・共有アカウント等の例外が攻撃面になる。ASKULのMFA例外、PR TIMESの共有アカウント・IP許可例外が明確な例である。

経営KPIとしては「MFA導入済み」「EDR導入済み」ではなく、**対象資産数に対する適用率と例外数・例外期限**を測る方が有効である。

## 2. 移行途上・レガシー資産

アサヒのゼロトラスト移行前PC、PR TIMESの旧管理画面のように、新しい統制が導入されていても旧経路・旧端末が残れば攻撃面は維持される。

「新方式の導入完了率」だけでなく、旧方式が完全に廃止されたかを確認する必要がある。

## 3. 境界機器

VPN、リモートアクセス装置、ネットワーク機器は複数事例で主要侵入面となった。2024年イセトー、2025年サンリオエンターテイメント、審調社、保険見直し本舗等が該当する。

これらはサーバーやPCと同様に、資産台帳、外部露出、認証、脆弱性、EOL、ログ、監視の対象とする必要がある。

## 4. データ配置・保持

イセトーでは、作業効率のための便宜保存と削除不徹底が被害量を増やした。PR TIMESでは削除済みデータを復旧可能な状態で保持する設計が事故後に見直された。侵入防止だけでなく、**侵害された時点で存在するデータ量**が最終被害を決める。

## 5. 初動と根絶の差

PR TIMESは検知当日に遮断した後も残存プロセスが活動した。ASKULは社内ネットワークの物理遮断後も外部クラウドへの不正アクセスが発生した。NTTコミュニケーションズは最初の装置対応後に別装置の侵害を特定した。

従って `containment` を一つの時刻にせず、`initial_block`、`scope_confirmation`、`credential_reset`、`persistence_eradication`、`clean_restoration` を分ける。

# 「PDFや認証があったのに侵害された」の解釈原則

1. 文書・認証の存在は、統制の設計・宣言・審査範囲の証拠である。
2. 事故発生だけでは、文書が虚偽だった、認証が無意味だったとは判断しない。
3. 実際に破られた資産が、その統制の適用範囲だったかを確認する。
4. 適用範囲だった場合も、設計不足、例外、運用逸脱、移行途上、未知の攻撃、検知・対応速度を分ける。
5. 事故後の認証停止・行政指導・内部統制評価は、第三者が不備をどう評価したかを示す強い予後証拠として扱う。

# 実務上の観測項目

企業の平時資料を読む場合、今後は少なくとも次を抽出する。

- MFA/EDR/SOC/SASE/ゼロトラスト等の対象範囲と適用率
- 例外アカウント・例外端末・例外ネットワークの件数と期限
- 境界機器の資産・脆弱性・EOL管理
- 管理者・委託先アカウントの個人識別、共有禁止、棚卸し
- データの正規保存領域、一時コピー、削除期限、バックアップ保持
- ログ対象範囲・保持期間・24時間監視の対象
- 復元試験、攻撃者から独立したバックアップ、クリーン環境再構築能力
- 事故後の認証停止、監督当局命令、内部統制評価、役員責任、決算影響

これらを持たない「当社はセキュリティを強化しています」という記述は、Denno Watchでは強い防御証拠として扱わない。
