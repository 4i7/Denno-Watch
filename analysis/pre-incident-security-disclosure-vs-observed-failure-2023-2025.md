# 目的

企業の統合報告書やサステナビリティ資料には、「情報セキュリティ強化」「CISO」「CSIRT」「MFA」「ゼロトラスト」「ISMS」「SOC」等が記載される。重大事故後にこれらの文言だけを引用すると、「十分な対策をしていたのに不可避だった」または逆に「公表内容が虚偽だった」と短絡しやすい。

本資料は、事故前に公表されていた統制を**その時点の文書上の事実**として保存し、侵害後に判明した失敗境界と比較する。統制が存在したことと、侵害資産へ一貫して適用されていたことを同一視しない。

# 評価ルール

1. 事故後に初めて導入された対策を事故前能力へ遡及しない。
2. 「目標」「計画」「導入率」「認証維持」「教育実施」を分離する。
3. グループ全体の方針と、実際に侵害された端末・拠点・委託先の設定を分離する。
4. ISO/ISMS等の認証を「侵害されない証明」とみなさない。
5. 侵害後に会社自身が認めた欠陥は、外部推測より優先する。
6. 事故前文書が確認できない場合、「対策なし」と書かない。

# カシオ — 数値KPIがあってもグローバル適用差が残った

カシオの統合報告書2024は、マテリアリティ「DXの推進と情報セキュリティの強化」の中で、ISMS認証維持、ゼロトラストネットワークのグループ会社導入率、国内外従業員への基礎教育、システム管理者向け専門教育、サイバーセキュリティ訓練を明示していた。特にゼロトラスト導入率は2024年度60%、2025年度90%という段階目標だった。[^casio-ir2024]

2024年10月のランサムウェア後、カシオ自身は「システム・セキュリティの強化を推進していたが、フィッシングメール対策及び海外拠点を含むグローバルでのネットワークセキュリティ体制に一部不備があった」と説明した。[^casio-result]

この組合せは重要である。事故前資料は「未対策」ではなく、**導入途中・適用範囲に差がある状態**を示していた。事故後にはSOC導入100%、第三者監査、フィッシング訓練等が新しいKPIとして設定された。[^casio-risk]

# IIJ — セキュリティ提供者でも第三者製品のゼロデイと検知遅延は残る

IIJの統合報告2024にはSOC、人材育成、警察とのサイバー捜査人材育成協力等が掲載され、セキュリティを中核能力として外部にも提供していた。[^iij-ir2024]

一方、IIJ Secure MXでは2024年8月3日以降に不正アクセスが発生し、2025年4月10日に漏えい可能性を確認した。原因は第三者製Active! mailの当時未発見脆弱性で、事案を通じて初めて明らかになった。[^iij-first][^iij-second]

ここから「SOCが無意味だった」とは言えない。比較すべきは、**SOCで監視可能だったテレメトリ、第三者製品内部で起きた挙動、検知ルール、サービス設備の長期滞留**である。

# 富士通 — 強いガバナンス開示と端末侵害を同時に記録する

富士通の2023年サステナビリティ資料は、専任CISO、グループの情報セキュリティ責任体制、MFAの国内展開、全社セキュリティ点検、脆弱性対応、監視強化を記載していた。[^fujitsu-2023]

2024年3月には複数業務PCでマルウェアを確認し、7月の調査結果では1台を起点に他の業務PCへ影響を広げる挙動が確認された。[^fujitsu-first][^fujitsu-final]

この事例は、経営・ルール面の成熟度と、端末で侵入・横展開を防ぎ検知する実効性を別々に測る必要性を示す。

# アサヒ — 移行前資産が残る期間を独立したリスクとして扱う

2026年2月の株主向け説明で、アサヒは2025年事故について、ゼロトラストモデルへの移行前の一部PCが暗号化され、同端末の情報の一部が窃取されたと公表した。また、攻撃者は約10日前に拠点ネットワーク機器から侵入し、パスワードの弱点を利用して管理権限を取得したと説明した。[^asahi-shareholder]

ここで重要なのは「ゼロトラストを導入していた／いなかった」の二値ではない。大規模企業では移行が年単位となるため、旧ネットワーク・旧端末・例外接続を何台・何拠点残しているかが実際の攻撃面になる。

# NTT西日本 — 外部攻撃対策の成熟度と内部不正統制は別

2023年に発覚した顧客情報持ち出しでは、コールセンタシステムの運用保守に従事した元派遣社員が情報を持ち出していた。事故後の外部専門家を交えた調査を受け、NTT西日本グループは内部不正リスクを考慮したシステム対処、リスク可視化、委託先監督等を体系化し、2024年9月から半期ごとに進捗を公開した。2026年9月時点でも継続更新されている。[^ntt-first][^ntt-progress]

これは、外部サイバー攻撃に強い企業でも、正当な運用権限を持つ内部・委託人員の大量取得を別の設計で防ぐ必要があることを示す。

# 比較から得られる共通構造

## 1. 「導入済み」より適用率と例外を見る

- ゼロトラスト導入率。
- EDR適用率。
- MFAの対象範囲。
- 海外拠点・子会社。
- 委託先・BPO。
- 開発環境。
- 旧端末・旧サーバー。

## 2. 認証・管理権限が境界を越える

LINEヤフー、アサヒ、DMM/Ginco、NTT西日本などでは、ネットワーク境界そのものより、認証・管理権限・委託関係が被害を増幅した。

## 3. セキュリティ製品・認証制度だけではゼロデイを消せない

IIJの事例は、セキュリティサービス自体に第三者製品が含まれ、その未発見脆弱性が長期間悪用され得ることを示す。したがって製品選定・認証だけでなく、侵害前提の挙動監視、証拠保持、強制資格情報ローテーションが必要になる。

## 4. 事故後に追加された統制は、事故前の欠落を直接証明しない

事故後にEDR、MFA、SOC等を「強化」したからといって、それらが事故前に一切存在しなかったとは限らない。対象範囲、設定、運用強度が変わった可能性を保持する。
