# 目的

Denno Watchの中心は日本の組織に関する公開インシデント記録である。一方、国内の新しい事例だけでは、事故から数年後の訴訟・保険・規制・信用、巨大な第三者集中、海外特有の攻撃キャンペーン等について十分な観測期間がない。

このため、**日本の防御判断へ再利用価値が高い海外ケースだけを、国内事例集から明確に分離して収録する**。

# 国内事例と混ぜない

海外比較ケースには必ず次を付ける。

```yaml
comparative_case: true
included_in_japan_corpus: false
incident:
  jurisdiction: US  # または該当法域 / global
```

海外ケースは次へ含めない。

- 「2026年日本の重大インシデント42件」等の国内件数。
- 国内事例だけを母集団とする割合・頻度。
- 日本企業の平均損失や法的負担としての直接推定。
- 日本の制度上の義務を説明する根拠としての単純転用。

# 収録条件

少なくとも一つを満たし、かつ日本の防御判断へ明確な比較価値があるものを選ぶ。

1. 技術復旧後の長期予後が一次資料で数年追跡できる。
2. 単一企業を超える社会・サプライチェーン・第三者集中リスクが観測できる。
3. 認証、SaaS共有責任、委託先、管理面等の事故成立条件が具体的に公表されている。
4. ゼロデイ一斉悪用等、国内事例集だけでは十分に観測できない失敗モードを補完する。
5. 事故費用、保険、訴訟、規制等が企業の正式開示・公的資料から追跡できる。

知名度だけでは選ばない。

# 根拠資料の優先順位

国内事例と同様に一次資料を優先する。

1. 被害組織・製品提供者の正式開示。
2. 規制当局・政府機関・裁判所・証券開示。
3. 直接対応したインシデント対応・脅威インテリジェンス組織の技術報告。
4. 直接影響を受けた下流組織の正式開示。
5. 信頼性の高い二次報道。

攻撃者主張、犯罪フォーラム上の投稿、匿名情報は、独立裏付けがある場合または「主張の存在」自体を記録する場合に限定する。

# 必須構成

海外比較ケースは原則として次を含む。

1. **概要** — なぜ比較価値があるかまで含む。
2. **公開情報で確認できる時系列** — 初期侵入、検知、公表、復旧、長期更新を分離。
3. **影響** — 機密性・完全性・可用性・下流・財務・本人保護。
4. **技術的に確認できた事項** — 公開根拠の範囲だけ。
5. **対応と復旧** — 封じ込め、根絶、技術復旧、業務復旧を分離。
6. **現在の状況と予後** — 最新の訴訟、規制、保険、財務、本人保護等。
7. **防御上の教訓** — 日本でも再利用可能な構造。
8. **日本の事例へ読み替える際の注意** — 制度差と適用限界。
9. **不明点・未公表事項** — 推測を確定事実にしない。

# 時間軸の扱い

海外事例は「最初の攻撃日」だけで並べない。

- `earliest_known_activity`: 最も早い確認済み活動。
- `detected_at`: 被害組織の検知。
- `first_disclosed_at`: 最初の公開。
- `latest_public_update`: 記録へ反映した最新一次情報。
- `public_record_checked_at`: より新しい公開がないか確認した日時。

技術修正から数年後のSEC開示、規制、裁判等も `latest_public_update` の対象になり得る。

# 海外金額の扱い

海外ケースのドル・ユーロ等は、原資料の通貨を維持する。為替換算は、比較目的が明確で換算日時・レートを示せる場合を除き行わない。

海外の事故費用を日本企業の予算へ直接当てはめない。使うのは次の構造である。

- 直接対応費だけで終わらない。
- 事業中断、下流支援、通知、訴訟、保険、再構築が別会計期間に現れる。
- 最終費用が事故年に確定しない。

# 法制度の扱い

HIPAA、SEC開示、米国集団訴訟、多地区訴訟、州法、EU DORA等は日本法と異なる。

したがって、海外ケースから国内向けに導くのは原則として次に限定する。

- 攻撃経路・成立条件。
- 集中・依存構造。
- 防御・復旧設計。
- 影響が時間とともに成熟する構造。
- 経営が準備すべき意思決定項目。

法的義務、期限、賠償額は日本の一次資料を別に確認する。

# 国内事例とのリンク

各海外ケースは、どの国内パターンを補完するかを明示する。

例:

- 高集中な医療・決済基盤 → 共有ISP、BPO、物流、通信等。
- SaaS顧客認証情報 → BI、クラウド、GitHub、委託先アクセス。
- 委託IT支援へのソーシャルエンジニアリング → ヘルプデスク、管理者再認証、委託先権限。
- ゼロデイ一斉悪用 → インターネット公開製品、ファイル転送、ネットワーク機器、共通製品依存。

# 更新基準

海外比較ケースは国内の速報監視より更新頻度を低くしてよいが、次のイベントは重要更新とする。

- 最終影響人数・件数の大幅訂正。
- 原因・侵入経路の正式確定または訂正。
- 重要サービスの全面復旧・廃止。
- 規制当局の処分・調査終結。
- 大規模和解・判決・集団認定。
- 保険枠の消尽、巨額引当、事故費用の重要更新。
- 二次悪用・再侵入・追加流出。

新情報がないだけで `latest_public_update` を更新しない。再確認日時は `public_record_checked_at` に置く。

# 最終原則

海外ケースは「海外の方が深刻だ」と示すためではない。国内事例だけでは時間的に見えないものを補い、**事故発生から数年後まで、どの負債が残り、どの防御設計が再利用できるか**を学ぶために使う。
